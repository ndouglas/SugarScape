**Goal:**
- a GOAP planner, verified on STRIPS domains with known optimal plan lengths;
- a foraging domain where travel costs time;
- the marginal-value rule as a baseline;
- "knowing the map";
- the marginal value theorem test Minds 3 couldn't run, and whether memory pays a mind that prices travel.

**Architecture:**
- `minds/goap.rs` plans over any `Domain` by interning states to indices and running Minds 2's `astar`. Goal states connect by a zero-cost edge to a sentinel goal node.
- `minds/goap/strips.rs` is for verification. `minds/goap/forage.rs` plans over a Flump's best K known sites, with state = (position, harvested mask).
- `minds/mvt.rs` is Constantino and Daw's rule.
- `DecisionRule::{Goap, Mvt}` go through the seam and end in `movement::arrive`.

**Tech Stack:** Rust (sugarscape-core, sugarscape-wasm), `survey/`, TypeScript and Vitest (`web/`).

**Spec:** `docs/superpowers/specs/2026-09-28-minds-4-goap-design.md`

## Global Constraints

- Every existing golden entry, legacy fixture and pinned fingerprint stays green and **unedited**. The new rules, `goap`, `mvt` and `memory.prior` default off and draw nothing new.
- The planner draws no random numbers. Among equal-cost plans, the first steps go to `movement::choose`: rule M's tie rule and draw.
- GOAP and MVT require `movement.mode: walk`. `memory.prior: map` requires `memory.span > 0`.
- The planner's expansion limit is 4 096. Past it, the Flump falls back to the rate choice (best value ÷ (distance + 1)).
- The foraging domain's state is (position ∈ own site plus K candidates, harvested bitmask). Gathered sugar is derived, never stored, so states are finite: at most (K + 1)·2^K with K ≤ 12.
- Deterministic and portable. No new `ln`/`exp`/`pow`. Ties by the stated order.
- American spelling. Titles follow `titles.rs`. Every commit ends with `Claude-Session: https://claude.ai/code/session_01BxjiP46rwioLoJSaqLMDiJ`.

### Task 2: The GOAP planner, verified on STRIPS domains

**Files:**
- `crates/sugarscape-core/src/minds/goap.rs` (new): `pub mod goap;` in `minds/mod.rs`, and `goap/strips.rs` as a submodule, either a `goap/` directory with `mod.rs` or `#[path]`; follow the repo's style.
- `crates/sugarscape-core/tests/goap.rs` (new).

**Interfaces:**

```rust
/// A planning domain (Minds 4): states, actions with costs, a goal and an
/// admissible heuristic.
pub trait Domain {
    type State: Clone + Eq + std::hash::Hash;
    type Action: Clone;
    /// Applicable actions from `s`, each with its cost (> 0) and the state it leads to, in a
    /// fixed order (the tie rule's push order).
    fn actions(&self, s: &Self::State, out: &mut Vec<(Self::Action, f64, Self::State)>);
    fn is_goal(&self, s: &Self::State) -> bool;
    /// A lower bound on the cost from `s` to any goal state (0 at goal states).
    fn heuristic(&self, s: &Self::State) -> f64;
}

/// A found plan: its actions in order and its cost.
pub struct Plan<A> { pub actions: Vec<A>, pub cost: f64, pub expanded: usize }

/// The cheapest plan from `start` to a goal state, or `None` (unreachable, or more than `limit`
/// expansions).
pub fn plan<D: Domain>(domain: &D, start: D::State, limit: usize) -> Option<Plan<D::Action>>;
```

**Implementation:**
- Intern states to `usize` indices in a `RefCell<HashMap<State, usize>>` plus a `Vec<State>`, and store each edge's action.
- Implement `minds::astar::Graph` over the interned indices. Every goal state gets one extra edge, of cost 0, to a sentinel index `usize::MAX`, and that sentinel is A*'s goal.
- The sentinel's heuristic is 0, and a goal state's heuristic is 0, so consistency is preserved.
- Rebuild the action list from the path's edges.
- A* draws nothing, and the interner's `HashMap` is only looked up, never iterated.

**`strips.rs`:**
- `Strips { facts: usize (≤ 64), actions: Vec<StripsAction { name: String, pre: u64, add: u64, del: u64, cost: f64 }>, goal: u64 }`.
- The state is a `u64` fact set. `actions` yields each action whose preconditions hold, in list order.
- The heuristic is the number of unsatisfied goal facts × the minimum action cost. That's admissible only if each action adds at most one goal fact, so use 0 (uninformed) when that isn't guaranteed. Verification needs optimality, not speed.
- Generators:
  - `gripper(n)`: two rooms, two grippers, n balls, unit costs. Goal: all balls in room B.
  - `logistics_trucks(n)`: n cities, each with a truck and one package to move between two locations, per Helmert and Mattmüller.
  - `logistics_one_truck(n)`: one truck, n packages in one city.
  - `blocks_family(n)`: Helmert and Mattmüller's 4-operator blocks family with h* = 4n − 2. Read the construction in `papers/planning/helmert-mattmuller-2007-accuracy-of-admissible-heuristics.pdf` and cite its section in a doc comment.

**Steps:**
- [ ] **Step 1: Write the failing tests** (`tests/goap.rs`):
  - Gripper: the optimal cost is 3n − 1 for even n and 3n for odd n, for n = 1–8.
  - Both logistics families: 4n, for n = 1–6.
  - The blocks family: 4n − 2, for n = 1–6.
  - 500 random STRIPS instances (seeded `rand_pcg`, 6–12 facts, 4–12 actions, costs 1–3): `plan`'s cost equals a Dijkstra over the fact-set graph written in the test. Agree on unreachability.
  - Unit tests in `goap.rs`: the start is already a goal (an empty plan, cost 0); an unreachable goal; the limit.
- [ ] **Step 2: Run them and check they fail.**
- [ ] **Step 3: Implement.**
- [ ] **Step 4: Run** `cargo test -p sugarscape-core --test goap --release && cargo test -p sugarscape-core --lib minds`.
- [ ] **Step 5: Commit** ("Minds 4: a GOAP planner, verified on gripper, logistics, blocks and random STRIPS instances").

If the blocks family's construction can't be recovered from the paper, drop that one test and say so in the report. Gripper and logistics carry the verification.

### Task 4: The foraging domain and the GOAP rule

**Files:**
- `minds/goap/forage.rs` (new);
- `minds/mod.rs` (the `Goap` dispatch);
- `agent.rs` (`Agent.goap_plan: Vec<Pos>`, the remaining targets; added to the three literals);
- `edit.rs` (`AgentView.goap: Option<GoapView { steps: Vec<[u32; 2]>, gathers: f64, goal: f64 }>`, `Some` only under GOAP);
- `world.rs` `TickEvents` (`plans: u32`, `plan_steps_sum: u32`, `plans_with_remembered: u32`).

**The domain:**
- **Candidates.** `movement::candidates_with_memory(world, id)`, sorted by value descending, then distance ascending, then site index. Take the top K, and always include the own site (index 0).
- **State.** `(pos: u8, mask: u16)`. `pos` 0 is the own site; 1..=K are candidates.
- **`Harvest(i)`.** Unharvested i, cost `lattice_distance(pos_site, i_site) + 1`.
  - The next state is `(i, mask | bit i)`.
  - Harvesting the own site in place costs 1.
  - The gathered total of a state is the sum of the harvested candidates' values.
- **Goal and heuristic.**
  - Goal: gathered ≥ G, where G = metabolism × horizon. With metabolism 0 (the mean over goods ≥ 2 is the good-0 metabolism), G = 0 and the start state is a goal: the Flump stays.
  - Heuristic: `ceil((G − gathered) / v_max)` over unharvested values, 0 at goal states. If `v_max` is 0 and gathered < G, the goal is unreachable: return `f64::INFINITY`, or prune.

**Deciding** (`Goap` rule):
1. If the Flump has a plan, check the next target. It must still be a candidate site, not occupied by another Flump, and reachable: not `walled_apart`, and the last A* didn't fail on it. If the target is in sight, its true value must be at least half the value it was planned at; store the planned values alongside the targets.
   - If the check passes, walk to it (`arrive`) and pop the target on arrival.
   - Otherwise drop the plan.
2. With no plan:
   - Plan with limit 4 096.
   - If the plan is empty (already at goal), stay.
   - If there's no plan (unreachable or over the limit), take the fallback: the candidate maximizing value ÷ (distance + 1), with rule M's tie rule through `choose` over the maximal entries.
   - Otherwise store the plan's targets.
   - Among the first steps of equal-cost plans, break ties through `choose`. Practical form: collect all first actions whose plan cost equals the optimum, by running A* with each first action forced. Or accept A*'s deterministic tie order, and then drop "the same tie draw" from the reduction test. Choose the simpler, and state it.
3. **Counting.** Count `plans`, `plan_steps_sum`, and `plans_with_remembered` when any target is a remembered out-of-sight entry. Also count `moves`, `remembered_moves` and belief error as Minds 3's `record_choice` does, for the target chosen.

**Steps:**
- [ ] **Step 1: Write the failing tests:**
  - a hand-built world where the cheapest plan to gather G harvests two near sites rather than one far rich site;
  - a far rich patch beats near scraps when G is large;
  - invalidation: the next target is taken, so the Flump replans that tick (Review Focus 2);
  - no known sugar: the Flump stays or takes the fallback, with no panic (Review Focus 1);
  - `goap_plan` isn't hashed (like `plan`);
  - the reduction: through a `#[cfg(test)]` hook that zeroes travel cost, with K covering all sight candidates and H = 1, GOAP's first target equals rule M's choice on 200 random hand-built neighborhoods.
- [ ] **Step 2: Run them and check they fail.**
- [ ] **Step 3: Implement.**
- [ ] **Step 4: Run** `cargo test -p sugarscape-core --release` (golden unchanged).

### Task 5: The marginal-value rule

**Files:** `minds/mvt.rs` (new); `agent.rs` (`Agent.rate: f64`, starting at the metabolism for every agent, with no draw, and `Agent.leaving: Option<Pos>`); `minds/mod.rs` (dispatch).

- Each tick, after the move:
  - `rate += alpha · (gain − rate)`, where gain is good 0's harvest this tick (0 on travel ticks);
  - clamp at ≥ 0;
  - never NaN (Review Focus 5).
- **Deciding:**
  - If `leaving` is set, walk to it, and clear it on arrival or if it becomes occupied.
  - Otherwise, take the best candidate within lattice distance 1 of the Flump, its own site included, by believed value. If that value is ≥ `rate`, target it (rule M's tie rule over the local maxima).
  - Otherwise set `leaving` to the best known candidate by value (tie: nearer, then the lower index) and walk.
- Count `moves`, `remembered_moves` and belief error as Minds 3 does, and `leaves` in `TickEvents`.
- **Tests:**
  - the ρ update and clamp;
  - staying while the local value ≥ ρ;
  - leaving and committing;
  - clearing on arrival;
  - metabolism 0 with no gain (ρ decays to 0 and never goes negative).
- **Commit.**
